# ЛР №10 «Автоматизация CI/CD и развертывания распределенного приложения в Kubernetes»

Вариант 11 — «Аренда автомобилей» (C#/.NET 8). Работа продолжает линию ЛР №5 → №6 → №7 → №8 → №9:
предметная модель, протокол и механизмы отказоустойчивости сохранены в полном объеме. Приложение
собирается, тестируется, упаковывается в Docker и автоматически развертывается в кластер **Kubernetes (k3s)**
с помощью конвейера **Jenkins Pipeline (CI/CD)**.

В ЛР №10 ручные операции сборки, запуска тестов и обновления образов в оркестраторе полностью
заменены автоматизированным конвейером `Jenkinsfile` из 6 этапов:
1. `Checkout` — получение актуального коммита из Git-репозитория;
2. `Restore` — восстановление NuGet-зависимостей (`dotnet restore`);
3. `Build` — компиляция решения в конфигурации `Release` без повторного восстановления;
4. `Test` — запуск полного набора из 129 Unit-, нагрузочных и интеграционных тестов с формированием отчета `.trx`;
5. `Package` — автоматическая сборка Docker-образа `riot-server:%BUILD_NUMBER%`;
6. `Deploy` — перенос образа в containerd k3s-кластера и обновление Deployment с контролем статуса через `kubectl rollout status`.

## Протокол взаимодействия

Все запросы и ответы представляют собой строки JSON, завершающиеся переводом строки `\n`:

* **Запрос**: `{"operation": "<OperationName>", "data": { ... }}`
* **Ответ**:
  ```json
  {
    "success": true,
    "message": "...",
    "instance": "Primary",
    "events": "...",
    "consensus": "...",
    "data": { ... }
  }
  ```

Основные операции предметной области:
1. `SearchCar` — поиск свободных автомобилей по локации/модели;
2. `CreateRental` — создание аренды с фиксацией в Primary, репликацией в Replica, консенсусом узлов и публикацией события брокеру;
3. `ReturnCar` — возврат автомобиля и освобождение ресурса (`is_available = true`);
4. `ShowState` — чтение текущего состояния базы данных и номера версии LSN.

## Unit- и интеграционные тесты

Решение содержит **129 тестов**, охватывающих все подсистемы:
* `ContainerConfigTests` (35 тестов) — проверка многоэтапных Dockerfile, параметров k8s-манифестов (`replicas`, порты, переменные окружения, селекторы сервисов);
* `RequestHandlerTests` (18 тестов) — бизнес-логика предметной области, поиск, аренда, возврат, транзакции;
* `ReplicationTests` (15 тестов) — репликация между Primary и Replica, вычисление дельты, сверка LSN, полный sync;
* `ClusterConsensusTests` (20 тестов) — алгоритм выборов Bully, кворум большинства (Majority >= 3), устойчивость к сбоям узлов;
* `BrokerPubSubTests` (21 тест) — очереди событий, повторные попытки доставки, переподключение подписчиков;
* `LoadTests` (20 тестов) — многопоточная нагрузка и конкурентный доступ к общим ресурсам.

## Моделирование сбоев в конвейере

1. **Сбой тестирования (Сборка #4)**:
   При падении assertion в тестах `dotnet test` возвращает код 1, Jenkins завершает сборку со статусом `FAILURE`. Этапы создания образа (`Package`) и раскатки (`Deploy`) пропускаются, предотвращая развертывание дефектного кода.
2. **Сбой развертывания (Сборка #6)**:
   При указании некорректного тега Docker-образа Kubernetes фиксирует ошибку `ImagePullBackOff`. Контроллер Deployment сохраняет доступность старых подов, а команда `kubectl rollout status` завершается по таймауту, регистрируя сбой `Deploy` в Jenkins.

## Итоговая проверка сервиса в k3s

После автоматического развертывания версии **`riot-server:7`** через Service (`port-forward svc/riot-server 5000:5000`) выполнены 3 предметные операции:
1. `SearchCar` -> `SUCCESS`, возвращено 3 автомобиля, подтверждена работа версии `Primary [v2.0-cicd]`.
2. `CreateRental` -> `SUCCESS`, аренда #3 создана, достигнут кворум узлов консенсуса (`YES = 5, Majority = 3`), событие `RentalCreated` передано брокеру.
3. `ReturnCar` -> `SUCCESS`, автомобиль возвращен, состояние базы данных обновлено до `lsn = 6`.
